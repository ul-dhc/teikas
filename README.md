# Teikas

Astro static-site prototype for the bilingual Pēteris Šmits legend collection. The editorial workbook is authoritative; website JSON is generated by the existing Python converter and must not be edited by hand.

## Setup

Requires Node.js and Python 3.9+.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install openpyxl
npm install
```

## Regenerate and validate JSON

```sh
npm run data:generate
npm run test:data
```

The single publication path is `latvian_legends_master_data.xlsx` → `scripts/XLSXtoJSON.py` → `teikas_json/`. The converter validates sheet headers, IDs, relationships, coordinates and duplicates before writing output. Regeneration updates `dataset-manifest.json`, including its timestamp and source checksum.

## Develop and build

```sh
npm run dev
npm run check
npm run build
```

The development server prints the local URL. The production build is written to `build/` with trailing-slash routes suitable for static hosting, including `/teikas/{legend_id}/` for every record.

## Interface translations

All interface copy that is not part of the folklore collection is maintained in `translations/ui-translations.csv`. The columns are `key`, `lv`, `de`, and `en`. The CSV can be imported into Google Sheets and shared with editors; export it again as UTF-8 CSV before rebuilding the website. Google Sheets is an editorial workspace, not a website runtime dependency.

```sh
npm run i18n:generate  # CSV → src/i18n/ui.json
npm run i18n:export    # src/i18n/ui.json → CSV (for a fresh editorial export)
```

`i18n:generate` stops with an error if a key or any of the three translations is missing. Folklore texts, legend titles, person names, places, sources, and other scholarly data remain in the generated collection JSON and are never written to this translation file.

## Architecture

- `src/lib/data.ts` validates and indexes all generated datasets, resolves relationships, and creates the compact browse index.
- `src/pages/teikas/index.astro` provides browser-side search, filters, sorting, and pagination without sending legend texts.
- `src/pages/teikas/[id].astro` generates all canonical bilingual detail pages with `getStaticPaths()`.
- `interfeiss_paraugi/` remains the visual reference set; no generated imagery is used as scholarly content.

## Publish with GitHub Pages

1. Create a public GitHub repository named `<username>.github.io` and upload the contents of this folder to its `main` branch.
2. Open **Settings → Pages** in GitHub.
3. Under **Build and deployment**, select **GitHub Actions**.
4. The included workflow validates and builds the site, then publishes the `build/` directory automatically.

The current site uses root-relative canonical routes such as `/teikas/130101001/`. A root Pages repository (`<username>.github.io`) or a custom domain preserves these URLs. If the site must instead live under a project subpath such as `<username>.github.io/teikas-project/`, the route base must be changed before publishing.
